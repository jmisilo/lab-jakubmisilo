# @labjm/agent

Mastra personal assistant exposed through Studio and the Blooio-backed Chat SDK iMessage channel.

The previous AI SDK implementation is preserved in `archive-ai-sdk` for presentation and
historical reference only. It is not imported by the active application, included in the runtime
bundle, uploaded to Vercel, or covered by the active package's build and test commands.

## Capabilities

- Mastra observational memory with resource-scoped continuity
- Hierarchical PostgreSQL and pgvector knowledge
- Google Calendar and read-only Gmail through one OAuth connection
- One-time and recurring schedules delivered through QStash
- Images, PDFs, and videos with bounded in-memory attachment handling
- Calorie and macronutrient tracking
- Weather, local time, and OpenAI web search
- Mastra Platform production observability, scorers, and the pre-day summary workflow

## Local Development

Create `.env` from `.env.example`. Use a pooled Neon `DATABASE_URL` and enable pgvector once:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

Push the custom schema and start Studio:

```sh
pnpm --filter @labjm/agent db:push
pnpm --filter @labjm/agent dev
```

Open `http://localhost:4111`. Studio and generic agent APIs use `AGENT_API_TOKEN`; local development
falls back to `agent-local-dev-token`.

The iMessage webhook is:

```text
/api/agents/agent/channels/imessage/webhook
```

## Storage

Neon owns both persistence layers:

- Mastra manages memory, threads, messages, schedules, and workflow state in `mastra`.
- Drizzle manages knowledge, QStash delivery state, Google, and nutrition tables in `public`.

Custom application tables use the `agent_*` prefix. Mastra's in-process scheduler is disabled
because Vercel functions are ephemeral. Recurring definitions remain Mastra schedules, while
QStash triggers their execution route.

## Vercel Production

This follows the [Mastra Vercel deployment guide](https://mastra.ai/guides/deployment/vercel).
Create or link a Vercel project with:

- Root Directory: `apps/agent`
- Framework Preset: Other
- Build Command: `pnpm build`
- Output Directory: automatic detection (disable the override)
- Node.js: 24

`vercel.json` pins the package build command so Vercel does not replace it with an empty
Turbo-inferred build when deploying from the monorepo. Do not use Vercel's Mastra framework preset
with `VercelDeployer`: that preset treats `.mastra` as the output directory and overwrites the
`.vercel/output` routing generated by the deployer.

Set the variables from `.env.example`. Prefer a stable production URL for `AGENT_PUBLIC_URL`. Set
the same origin in `GOOGLE_OAUTH_REDIRECT_URI`:

```text
https://<agent-domain>/api/links/google/callback
```

Production traces, logs, and metrics are sent to Mastra Platform. Create an access token and set
`MASTRA_PLATFORM_ACCESS_TOKEN` and `MASTRA_PROJECT_ID` in Vercel:

```sh
pnpm --filter @labjm/agent exec mastra auth login
pnpm --filter @labjm/agent exec mastra auth tokens create agent-vercel-observability
```

Local development falls back to PostgreSQL-backed observability unless those platform variables
are set. Production intentionally does not duplicate observability events into PostgreSQL.

The native Mastra build keeps its generated dependency tree intact. If Vercel reports that the
function exceeds the applicable size limit, enable the project's large-function support or
reintroduce a targeted dependency-pruning step.

Configure Blooio to deliver to:

```text
https://<agent-domain>/api/agents/agent/channels/imessage/webhook
```

Push the schema once for the production database, then deploy from the repository:

```sh
pnpm --filter @labjm/agent db:push
vercel --cwd apps/agent deploy --prod --force --yes
```

The project was previously configured with framework-specific presets. Use `Other` for remote
builds and keep the Build Command override as `pnpm build`. The Vercel deployer generates the Build
Output API artifact during that build.

Mastra serves Studio at `/` and mounts built-in server routes below `/api/mastra`. Application
routes use the remaining `/api` namespace: Google OAuth uses `/api/links/google/*`, QStash
delivers to `/api/jobs/schedules/execute`, and the iMessage webhook remains below
`/api/agents/*`.

The deployed Studio is served at the production origin and protected by `AGENT_API_TOKEN`. The
QStash execution route is public but accepts only signature-verified deliveries.
Verify the protected Mastra API with:

```sh
curl -H "Authorization: Bearer $AGENT_API_TOKEN" https://<agent-domain>/api/mastra/agents
```

After cutover, ask the agent to list current reminders once. Schedule inspection reconciles any
pre-existing Mastra recurring definitions with their QStash delivery triggers.

## Scheduling

`manage_schedule` lets the agent:

- create one-time and recurring schedules
- list schedules or inspect one exact schedule
- update title, prompt, time, or recurrence
- pause, resume, run now, complete the current occurrence, or cancel

One-time reminders are limited to seven days ahead. Recurring schedules cannot run more often than
hourly. Current limits are 10 active schedules of each kind per resource.
